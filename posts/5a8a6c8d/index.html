Live2d模型前端加密过程

发表于2026-11-09|更新于2026-11-09|web前端

🚨 遵循 AGPL-3.0 协议。
开源仓库不包含生产环境使用的密钥。
GitHub ：live2d-widget.js-secure

  • 要在moc文件加载前将其加密，加载后解密，这需要在加载过程中插入代码。所以需要重写加载模块。在l2d对应的加载模块中拦截数据请求，将获取的二进制数据进行XOR还原后，再交由Live2D渲染器解析。

  • 由于L2Dwidget.min.js源码混淆过，需要重新编译

  • 重写init函数，添加白名单拦截功能

  • json加密同理，只是需要注意下加载函数的位置不一样(在src\utils\ModelSettingJson.js文件中，修改LoadModelSetting方法)

  • 编译修改后的live2d-widget.js将lib文件夹里3个文件(map不需要)替换掉原始文件。

🔶 加密模型是为了防止本地脚本暴力穷举出模型。对抗逆向可以在加载模块里添加dead code和反调试循环，或者直接上JS虚拟机。

加密并构造init

🟢 以下是修改moc加载函数实例，防暴力破解可以用多字节流。

🟠 XOR 解密：重写live2d-widget.js/src/PlatformManager.js 中的 loadBytes方法，完成后编译live2d-widget.js，替代原始文件。

🟢 实现init函数，验证白名单。导入的时候要注意放在L2Dwidget.min.js后面

动态加载Live2d启动器

将Live2d脱离插件并加密后，使用JSVMP混淆加载模块，这种情况下虽然加载模块里已经写了防重调用，但PJAX每次刷新网页都会重复调用整个JS虚拟机，这严重影响了性能。

💡解决：通过监听PJAX的send和complete事件，动态加载启动模块。
